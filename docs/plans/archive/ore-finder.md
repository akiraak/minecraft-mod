# 鉱石さがし: 近くの石炭・鉄・ダイヤの位置を出す

- 作成: 2026-11-14 PST
- 状態: 完了（2026-11-14）。鉄とダイヤの座標と距離を数値で出す形になり、0.3.0 として Realm に入っている。光らせる目印は試したうえでやめた。経過は末尾の「経過」

## 目的・背景

MOD のアイデアを出したあと（`docs/mod-ideas.md`）、利用者から一覧に無い希望が出た: 「鉱物の位置が知りたい」。やりとりで決まったことは次のとおり（2026-11-14）。

- とりあえず常に表示する（キーやアイテムで切り替える形は、いまは作らない）
- 石炭、鉄、ダイヤモンドの、それぞれいちばん近い位置をテキストで出す
- ゲームの画面の中で、その位置を光らせることができるなら、そうしたい

## 確かめたこと（型定義。ゲームでは未確認）

`@minecraft/server` 2.11.0 の `index.d.ts` で見た。

- `dimension.getBlocks(volume, options, allowUnloadedChunks)`: 範囲内で条件に合うブロックの座標の一覧を返す。`options` に `includeTypes`（ブロックの種類）、`closest`（近い順に何個）、`location`（どこから近いか）を渡せる
- `player.spawnParticle(effectName, location, molangVariables)`: そのプレイヤーにだけ見えるパーティクルを出す
- 好きなキーは検知できない。検知できるボタンは `Jump` と `Sneak` だけ（`InputButton`）
- 鉱石のブロックの ID は `@minecraft/vanilla-data` 1.26.60 で確認: `minecraft:coal_ore` / `deepslate_coal_ore`、`iron_ore` / `deepslate_iron_ore`、`diamond_ore` / `deepslate_diamond_ore`
- パーティクルは Mojang の `bedrock-samples`（`v1.26.60.5`）の `minecraft:colored_flame_particle` を使う。`variable.color` で色を指定できる
- 壁の向こうまで見える描画ができそうな `@minecraft/debug-utilities` は、npm にベータ版しか無い。Realms では使えない

## 分かっていないこと

- 一度に調べられる範囲の広さの上限（`getBlocks` は範囲が大きすぎるとエラーにするらしいが、数字は書かれていない）
- 毎秒調べたときの重さ
- 石の向こうにあるパーティクルが見えるか。見えない見込み（ふつうのパーティクルはブロックに隠れる）。その場合、光って見えるのは鉱石が洞窟などで露出しているときだけになる
- Info HUD の表示を複数行にできるか（タイトルの文字列に改行を入れる）

## 対応方針

Info HUD（`addons/info-hud/`）に足す。別の mod にはしない（スクリプトから画面へ文字を渡す道が 1 本のため）。

- さがす
  - プレイヤーごとに 1 秒に 1 回、自分を中心に前後左右上下 16 ブロックの範囲を調べる。高さはディメンションの範囲に収める
  - 石炭・鉄・ダイヤのそれぞれについて、いちばん近い 1 個の座標を取る（深層岩の鉱石も同じ種類として扱う）
  - 読み込まれていないチャンクは飛ばす
  - エラーになったら、その文面を表示の中に出す（ログも残す）。利用者に見たまま報告してもらえるようにするため
- テキスト
  - Info HUD の 1 行目（時刻と座標）の下に、鉱石ごとに 1 行ずつ足す

    ```
    06:58  -28, -52, 48
    石炭  -30, -50, 50  3m
    鉄  -20, -47, 41  12m
    ダイヤ  なし
    ```

  - 距離は、足元のブロックから鉱石のブロックまでの直線距離（小数は四捨五入）
- 光らせる
  - 0.5 秒ごとに、見つけた鉱石のブロックの 6 つの面のすぐ外側に、色つきの炎のパーティクルを出す（本人にだけ見える）
  - 色: 石炭は白、鉄は橙、ダイヤは水色

## 影響範囲

- `addons/info-hud/behavior_pack/scripts/`（`main.js`、`format.js`、新しい `ore-finder.js`）
- リソースパックは変えない
- Realm に入れると、参加者全員に鉱石の位置が出る。探す楽しみが減るので、入れる前に利用者が決める

## テスト方針

- Step 1: 文面の組み立てを Node で確かめる
- Step 2: ローカルのワールドで利用者が確かめる
  - 左上に 4 行出るか（改行が効くか）
  - 表示された座標を掘って、その鉱石が本当にあるか
  - 近くに無い種類が「なし」になるか
  - 洞窟で露出した鉱石が光って見えるか。埋まっている鉱石はどう見えるか
  - 動きが重くならないか
  - エラーの文面が出たら、そのまま教えてもらう
- Step 3: 結果を見て、範囲の広さ、間隔、光らせ方を直す

## 経過

- 2026-11-14 22:30 ごろ、1 回目の確認（ローカルのワールド）: 利用者の報告は「時計も座標も出なくなった」。鉱石の行だけでなく、Info HUD の表示が全部出なくなった
- 原因の推定（確かめていない）: `ore-finder.js` が読み込み時に `new MolangVariableMap()` と `setColorRGB` を呼んでいた。Script API v2 では、読み込み時（ワールドの準備前）に呼べる API が限られていて、呼べないものを呼ぶと失敗する。`main.js` は `ore-finder.js` を読み込むので、スクリプト全体が動かなくなったと見ている。型定義では、`setColorRGB` に「読み込み時に呼べる」の印（`early-execution-allowed`）が無い
- 別の可能性: タイトルの文字列に改行を入れたことで、画面定義の側が文字を出せなくなった
- コンテンツログはゲームを終了するまでファイルに書かれないようで、この時点では空だった。次に利用者がゲームを起動し直したあとで、失敗した回のログを読んで原因を確かめる
- 直したこと: 色の指定を、最初に光らせるときに作るようにした。ゲームの API をまねた代役も、読み込み時に API を呼ぶと失敗するように変えて、通ることを確かめた
- 原因の確定: ゲームを終了したあとのコンテンツログに `ReferenceError: Native constructor for [MolangVariableMap] cannot be used in early execution.`（`ore-finder.js`）と、`main.js` が失敗したという行があった。推定どおり
- 2 回目の確認: 利用者の報告は「テキストの表示は出た」。複数行の表示（改行）と、鉱石をさがす部分は動いている。座標が合っているか、光り方、重さは聞いていない
- 利用者の質問: 露出した鉱石ではなく、地下に埋まっている場所を表示できないか
  - 埋まっているブロックそのものを壁越しに光らせる方法は、安定版では見つかっていない（ふつうのパーティクルはブロックに隠れる見込み。壁越しに描ける `@minecraft/debug-utilities` はベータ版だけ）
  - 代わりに「掘る場所の目印」を足した: 目から鉱石へまっすぐ線を引き、最初に当たるブロックの表面（手前の壁や床）にパーティクルを出す（`getBlockFromRay`）。ゲームでは未確認
  - ほかの案（未着手）: ロケーターバーに鉱石の方角を点で出す（`LocationWaypoint`。色を指定できる）
- 3 回目の確認: 利用者の報告は「光ったり目印が付いたりはない」。テキストは出ている。1 つ前の回のログには、スクリプトのエラーも警告も無かった（パーティクルを出す呼び出しは失敗していない）
- 原因は分かっていない。考えられること: パーティクルの種類（色つきの炎）が出ていない／小さくて気づかない、本人にだけ見える出し方が効いていない、線を引いて当たった場所の計算が違う
- 切り分けのために調査用の表示を足した（`debug-particles.js`、`main.js` の `DEBUG_PARTICLES`）。0.5 秒ごとに次を出す
  - 目の前 2 ブロックの左: 赤い炎（本人にだけ見える出し方。鉱石の目印と同じ）
  - 目の前 2 ブロックの右: 青い炎（全員に見える出し方）
  - 目の前 2 ブロックの少し上: 緑の粒（色の指定が要らない `minecraft:villager_happy`）
  - 見ているブロックの表面: 白い光の粒（`minecraft:endrod`、両方の出し方）
  - 左上の最後の行に `テスト: 面 0.50, 1.00, 0.25` のように、当たった場所の値（`faceLocation`）を出す
- 調査が済んだら `debug-particles.js` と `DEBUG_PARTICLES` を消す
- 4 回目の確認の結果（調査用の表示）
  - 緑の粒（`minecraft:villager_happy`、本人にだけ見える出し方）は、いくつも見えた
  - 赤い炎と青い炎（`minecraft:colored_flame_particle`、出し方は 2 通り）は見えなかった。色つきの炎は、この使い方では見えない。原因は分かっていない
  - `テスト:` の行は「見ている先にブロックなし」だった。そのとき 8 ブロック以内のブロックを見ていたかは分からないので、線を引く計算が合っているかは未確認のまま
- 5 回目に向けて変えたこと
  - 鉱石の目印（鉱石のまわりと、掘る場所の目印）を、見えることが分かった緑の粒にした。3 種類とも同じ緑で、まだ色分けはできていない
  - 色分けの候補を、目の前に左から順に出す: 橙の炎（`basic_flame_particle`）、青い炎（`blue_flame_particle`）、白い光（`endrod`）、赤いハート（`heart_particle`）、赤い粉（`redstone_ore_dust_particle`）。どれも色の指定が要らない種類
  - `テスト:` の行に、見ている先（30 ブロックまで）の `faceLocation` の値と、掘る場所の目印を出せた数（`目印 2/3` のように、見つけた鉱石のうち何個に出せたか）を出す
- 5 回目の確認の結果: 利用者の報告は「光もハートも見える」。白い光（`minecraft:endrod`）と赤いハート（`minecraft:heart_particle`）は見える。橙の炎・青い炎・赤い粉については聞けていない
- 利用者から「何を言っているのか分からないので整理して」と言われた。調査の頼み方が細かすぎた。調査用の表示（目の前の 5 つと `テスト:` の行）は消した
- 色分けを決めた: 石炭は緑の粒（`villager_happy`）、鉄は赤いハート（`heart_particle`）、ダイヤは白い光（`endrod`）。3 つとも、利用者が見えると報告した種類
- まだ確かめていないこと: 掘る場所の目印が壁や床に出るか、その方向が合っているか、表示された座標に鉱石があるか、重さ
- 6 回目の確認の結果: 利用者の報告は「石炭には緑が出る。白い光とハートはどこにいても出る。移動してもずっと出るので間違っているんじゃないか」
  - 計算の間違いではなく、目印の決め方が分かりにくかった。目印を「自分の目から鉱石へ引いた線が最初に当たる表面」に出していたので、鉄とダイヤが埋まっていると、歩くたびに目印が自分の近くの壁や床を移動し続けた
- 目印の決め方を変えた: 鉱石にいちばん近い空いているブロック（`minecraft:air`。鉱石から前後左右上下 8 ブロックまで）の中の、鉱石の側の壁ぎわに出す。プレイヤーの位置に依らないので、歩いても動かない。露出した鉱石なら鉱石の面のすぐ前になるので、鉱石のまわり 6 面に出していた分はやめた。8 ブロックより奥に埋まっている鉱石には目印を出さない（文字の座標だけ）
- 線を引く方法（`getBlockFromRay`）は使わなくなった
- まだ確かめていないこと: 新しい目印が期待どおりの場所に出るか、表示された座標に鉱石があるか、重さ
- 利用者の決定（2026-11-14）: 数値の表示だけで十分なので、目印（パーティクル）を出すのはやめる。石炭は表示から外す。新しい目印の出し方（鉱石にいちばん近い空いている場所に固定）は、ゲームで確かめないまま取り下げた
- いまの形: 左上に、時刻と座標の行と、鉄・ダイヤのいちばん近い座標と距離の行が出る。パーティクルは出さない
- 利用者の質問「鉄とダイヤ以外に重要な鉱物は何か」に候補を答えた。どれを足すかは利用者がまだ決めていない
- 利用者の決定（2026-11-14）: まずは鉄とダイヤだけでよい。画面の表記には日本語を使わない
- 表記を変えた: `鉄` → `Iron`、`ダイヤ` → `Diamond`、近くに無いときの `なし` → `--`、エラーのときの `鉱石さがし:` → `Ore search:`。名前と `--` は Claude が選んだ

  ```

  Iron  -20, -47, 41  12m
  Diamond  --
  ```

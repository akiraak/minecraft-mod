# MOD のアイデアを出す

- 作成: 2026-11-14 PST
- 状態: 完了（2026-11-14）。一覧は `docs/mod-ideas.md`。利用者は一覧に無い「鉱石さがし」を選び、`docs/plans/ore-finder.md` で進めている

## 目的・背景

このリポジトリでは、最初の実験として Info HUD（時刻と座標を左上に出す）を作り、mod を作って Realm で動かせることを確かめた。次に何を作るかは決まっていない（`CLAUDE.md` の「現状」）。利用者から「MOD のアイデアを出して」という依頼があったので、作れる範囲を確かめたうえで候補を並べ、利用者が選べるようにする。

このタスクで出すのはアイデアの一覧と、おすすめの順番まで。作るかどうか、どれを作るかは利用者が決める。

## 前提（分かっていること）

- 遊ぶ場所は Realms。作った mod は Realm のワールドに入れ、参加者全員に効く
- 使えるのは安定版の Script API（`@minecraft/server` 2.11.0）。ベータ API と `@minecraft/server-net` は Realms で使えない
- 見た目を変えるにはリソースパックが要る。HUD の配置を変える JSON UI は、ゲームで動かして確かめるしかなく、失敗がログに出ない。確認のたびに利用者の手が要る
- Info HUD は、スクリプトから HUD へ文字を渡す道としてタイトルを使っている。タイトルの文字列は 1 つしかないので、HUD に出す情報を増やすときは、別の mod にせず Info HUD の文面に足す形になる
- アクションバーは、Info HUD 0.2.0 で使わなくなったので空いている

## 分かっていないこと

- 利用者の遊び方（サバイバル中心か、建築か、探索か）、一緒に遊ぶ人数と顔ぶれ、いま不便に感じていること
- Realm に入れたパックを新しい版に入れ替える手順（`TODO.md` の info-hud の Step 6 で確かめる予定）。入れ替えが面倒なら、こまめに更新する種類の mod は向かない
- 第三者のアドオンを入れると実績が取れなくなるか

## 対応方針

### Step 1: 利用者に聞く

アイデアの向きを決めるために、次を聞く。答えが無い項目は、広めに候補を出す。

- どんな遊び方をしているか。誰と遊んでいるか
- いま不便なこと、面倒なこと、あったらいいと思っていること
- 入れたくない種類のもの（例: ゲームが簡単になりすぎるもの、ほかの参加者に見えてしまうもの）
- どのくらいの大きさのものを作りたいか（数時間で終わる小さなものか、何日もかけるものか）

### Step 2: 作れる範囲を確かめる

候補を出す前に、種類ごとに「安定版の API で Realms 上にできるか」を確かめる。記憶で書かず、`@minecraft/server` 2.11.0 の型定義（`npm pack @minecraft/server@2.11.0` の `index.d.ts`）と公式ドキュメントで見る。

- 画面に情報を出す: Info HUD に足せる情報（方角、バイオーム、ディメンション、月齢、天気、スポーン地点までの距離など）が API から取れるか
- 記録を残す: ワールドやプレイヤーにデータを保存する仕組み（ダイナミックプロパティ、スコアボード）
- 操作の入口: コマンドの追加、アイテムを使ったとき、フォームの画面（`@minecraft/server-ui`）が安定版で、Realms で使えるか
- 世界への働きかけ: ブロックやエンティティを置く・変える、アイテムを渡す、といった操作の範囲
- 新しいアイテム・ブロック・モブ: スクリプトではなくデータ（JSON）で足すもの。実験的機能のトグルが要らない範囲

確かめられなかったものは「未確認」と書き、アイデアの側にもその印を引き継ぐ。

### Step 3: アイデアを出す

種類をまたいで 10〜20 個出す。種類の例: 情報の表示、便利機能、記録と統計、遊びのルールやミニゲーム、新しいアイテムやブロック。

1 つずつ、次の項目をそろえる。

| 項目 | 内容 |
| --- | --- |
| 何ができるか | 遊んでいる人から見た動き（1〜2 文） |
| うれしい場面 | 誰が、どんなときに使うか |
| 使う仕組み | スクリプト、データ、リソースパック（JSON UI を含むか） |
| Realms での制限 | 全員に効くこと、使えない API、実績への影響など |
| 大きさ | 小（半日まで）／中（数日）／大（それ以上）。目安であって見積もりではない |
| 不確かな点 | Step 2 で未確認だったもの、ゲームで試さないと分からないもの |

### Step 4: 絞り込んで利用者に見せる

- 一覧を `docs/mod-ideas.md` にまとめる
- 「うれしさ」「確かさ（Step 2 で確認できたか）」「大きさ」で並べ、おすすめを 3 つ選んで理由を書く
- 利用者に見せて、作るものを選んでもらう

### Step 5: 選ばれたものをタスクにする

- 選ばれたアイデアを `TODO.md` に個別のタスクとして足す（それぞれ着手時にプランを作る）
- 選ばれなかったものは `docs/mod-ideas.md` に残す

## 影響範囲

- 足すのは文書だけ（`docs/mod-ideas.md`、`TODO.md`、`DONE.md`）。コードとパックは変えない
- ゲームと Realm には触らない

## テスト方針

- 「できる」と書いた仕組みは、型定義か公式ドキュメントのどこで確かめたかを一覧に書く。確かめていないものは「未確認」と書く
- 文書だけのタスクなので、ゲームでの確認はしない。選ばれたアイデアの確認は、それぞれのタスクで行う

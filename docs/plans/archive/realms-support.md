# Realms 対応: 作った mod を Realms のワールドで動かす

- 作成: 2026-11-14 PST
- 状態: 完了（2026-11-14）。利用者が Realm の画面からパックを有効にし、「表示された」と報告した（0.1.0、開発用フォルダのパックのまま）
- 実際の画面の道順: Realm Hub → 上の「ワールド」→「スロット」→ 有効なワールドの「ワールドを編集」→「ビヘイビアー パック」→「認証する」。バックアップは「ワールド」→「保存」→「アクティブなワールドを保存」
- プランの本文にある「ワールドをダウンロード」「鉛筆のアイコン」は古い画面の名前で、今の画面には無かった

## 目的・背景

利用者は Realms で遊んでいる。`game-clock` はローカルのワールドで動くことを確かめたが、配置先の `development_behavior_packs/` はローカルのワールド用で、Realms にはそのままでは効かない。作った mod を Realms のワールドで動かせるようにする。

## 対応方針

- Step 1: 調査。公式の情報（Microsoft Learn の Minecraft Creator、Minecraft のヘルプ）で次を確かめる
  - Realms のワールドにビヘイビアパックを入れる方法（画面の操作、必要な権限）
  - Realms で Script API が動く条件と制限（安定版の API、ベータ API、実験的機能、使えないモジュール）
  - 開発用フォルダのパックをそのまま使えるか、`.mcpack` にして取り込む必要があるか
  - パックを更新したときの反映の仕方（版の上げ方）
  - ほかの参加者への影響
- Step 2: 手順を決めて、必要な道具を作る（`.mcpack` を作るスクリプトなど。調査の結果しだい）
- Step 3: `game-clock` を Realms に入れて、利用者が表示を確かめる
- Step 4: 決まった手順を `CLAUDE.md` に書く

## 影響範囲

- このリポジトリ: `tools/`、`CLAUDE.md`、`TODO.md` / `DONE.md`
- Realms のワールド: パックを入れる操作は利用者がゲームの画面から行う。Claude は Realms のワールドを直接は触れない
- ほかの参加者がいる場合、ビヘイビアパックは全員に効く

## テスト方針

- 道具を作った場合は、できたファイルの中身（`manifest.json` が最上位にあること）を確かめる
- 最終の確認は、利用者が Realms のワールドに入って時刻の表示を見る

公式のヘルプ（help.minecraft.net）と minecraft.net のページは、取得が時間切れ・拒否になって本文を読めなかった。下の「検索の要約」は検索結果に出た要約で、本文で確かめたものではない。

分からないこと:

- `development_behavior_packs/` のパックが、Realm のパックの一覧に出るか
- パックを更新したときの反映の仕方（版を上げれば置き換わるか）
- Realm で実績が取れなくなるか、なるなら元に戻せるか

## 決めた手順（Step 2）

- 第一の方法: Realm の設定からビヘイビアパックを有効にする。ワールドを置き換えないので、今のワールドはそのまま残る
- 先に「ワールドをダウンロード」でバックアップを取る
- 一覧に `Game Clock` が出ないときは、`tools/pack.sh game-clock` で作った `dist/game-clock.mcpack` を Windows で開いて取り込む。同じ UUID のパックが二重になるので、先に `development_behavior_packs/game-clock/` を消す
- 「ワールドを置き換え」は使わない（Realm のワールドを上書きするため）
- `game-clock` は安定版の API だけを使うので、ベータ API の制限には当たらない

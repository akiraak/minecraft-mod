# info-hud（旧 game-clock）: 画面左上に時刻と座標を出す

- 作成: 2026-11-14 PST
- 状態: 完了（2026-11-14）。0.2.0 を利用者が Realm に入れた。その後の変更（鉱石の行、表示位置）は 0.3.0 として Realm に入っている。経過と出来上がった仕組みは下の「経過」以降。「対応方針」は着手時のもので、一部は変わった
- 名前: 2026-11-14 に `Game Clock`（`game-clock`）から `Info HUD`（`info-hud`）へ変えた。今後も表示が増える可能性があるので、時計に限らない名前にした（利用者の指示。名前は Claude が選び、利用者が了承）。UUID は変えていない。0.1.0 は `Game Clock` の名前のまま Realm に入っている

## 目的・背景

`game-clock` 0.1.0 は、ホットバーの上（アクションバー）に `N日目 HH:MM` を出している。利用者の希望は次のとおり。

- 画面の上部の左に出す
- `N日目` は消して `HH:MM` だけにする
- いま左上に出ているゲームの座標表示と合わせて、`HH:MM X:123 Y:456 Z:789` の 1 行にする

## 分かっていること

- アクションバーの位置はスクリプトから変えられない。位置を変えるには、リソースパックで画面の定義（JSON UI の `ui/hud_screen.json`）を書き換える
- ゲームの座標表示（`player_position`）は `root_panel/chat_stack`（左上の縦並び）の中にあり、文面はゲームが作る。スクリプトから時刻を足すことはできない
- スクリプトから HUD へ文字を渡す道は、タイトル（`#hud_title_text_string` のバインディング）かアクションバー（`$actionbar_text` の変数）。常に出しておく表示にはタイトルのバインディングを使う
- JSON UI は Bedrock Wiki が「廃止予定で、いずれ動かなくなる」と書いている。公式の資料は見つからなかった（Microsoft Learn の JSON UI のページは 404）

出どころ:

- バニラの定義: Mojang の `bedrock-samples`（タグ `v1.26.60.5`）の `resource_pack/ui/hud_screen.json`。インストール先の UI は `__brarchive` にまとめられていて直接は読めない
- 書き方: Bedrock Wiki の「Preserve Title Texts」と「Intro to JSON UI」

## 対応方針

- スクリプト（ビヘイビアパック）
  - 2 tick ごとに、各プレイヤーの `HH:MM X:.. Y:.. Z:..` を作る。座標は小数を切り捨てる（ゲームの表示と同じ足元のブロック座標）
  - 文面が前回と変わったときだけ、目印 `infohud:` を頭に付けてタイトルとして送る。5 秒ごとに変わっていなくても送り直す（HUD が作り直されたときのため）
  - アクションバーは使わなくなる。0.1.0 では、ベッドやレコードなどゲームがアクションバーに出す文字を上書きしていた
- リソースパック（新規）`ui/hud_screen.json`。バニラの定義に差分だけを重ねる
  - `info_hud_display`: 目印の付いたタイトルを覚えておき、目印を外して表示する。見た目はゲームの座標表示と同じ（黒い半透明の背景に白い文字）
  - `root_panel/chat_stack`: ゲームの座標表示の位置に `info_hud_display` を入れ、ゲームの座標表示を外す
  - `hud_title_text`: 目印の付いたタイトルは画面の中央に出さない
- ビヘイビアパックの `dependencies` にリソースパックを書く
- 版は 0.2.0 に上げる（Realm に上がっている 0.1.0 と区別するため）
- `tools/deploy.sh` はリソースパックも配置する。`tools/pack.sh` は両方を `.mcaddon` にまとめる

## 影響範囲

- `addons/info-hud/`（`behavior_pack/`、新しい `resource_pack/`）、`tools/`
- 参加者全員: 左上の表示がゲームの座標表示から置き換わる。「座標を表示」の設定がオフでも出る
- ほかのアドオンやコマンドがタイトルを出すと、プレイヤーが動くか時刻が変わった時点でこちらのタイトルに置き換わり、中央の表示が消える

## テスト方針

- Step 1: 整形の関数を Node で確かめる。JSON が正しいことを確かめる
- Step 2: ローカルのワールドで利用者が確かめる
  - 左上に `HH:MM X:.. Y:.. Z:..` が出て、歩くと座標が変わる
  - 画面の中央に `infohud:...` が出ない
  - ゲームの座標表示（`位置: ...`）が消えている
- Step 3: ローカルで良ければ Realm に入れる（0.1.0 を外して 0.2.0 を有効にする）

## 経過

- 2026-11-14 18:12 ごろ、1 回目の確認: 新しいワールドで両方のパックが有効になっていた（`world_behavior_packs.json` / `world_resource_packs.json` で確認）が、利用者の報告は「何も表示されなかった」。原因は特定できていない。チャットの 1 行が出たかは未確認。ゲームは起動し直されていなかった（17:05 から同じプロセス）。コンテンツログは無効だった
- 2 回目に向けて変えたこと（原因が分からないままの変更）
  - 表示の入れ方を、利用者の PC に入っている `bedrock-ui-plus` が実際に使っている書き方に寄せた: `root_panel/chat_stack` へ `insert_front` で入れ、ゲームの座標表示は `"root_panel/chat_stack/player_position": { "ignored": true }` で外す（1 回目は `insert_before` と `remove` を使っていた）
  - タイトルがまだ届いていないときは `--:--` を出す。これで「表示の枠は入ったが文面が届いていない」のか「枠が入っていない」のかを見分けられる
- 1 回目についての利用者の報告: チャットの 1 行は出た（スクリプトは動いている）。左上は空で、チャットの文字が 2 行目に出た（空の枠が 1 行目にあったと見られる）
- 2026-11-14 18:36 ごろ、2 回目の確認（調査用の 3 行）
  - 1 行目の固定の文字 `Info HUD test` は出た
  - 2 行目の、タイトルの文字列をそのまま出す行は `infohud:07:08 X:-127 Y:63 Z:70` と出た。スクリプトの文面は画面定義まで届いている
  - 3 行目の、Bedrock Wiki の「Preserve Title Texts」の書き方（`property_bag` と `visibility_changed`、子の `data_control` から `source_control_name` で読む）の行は空だった。初期値の `--:--` も出なかった
  - コンテンツログのファイルは作られたが空（0 行）。JSON UI の失敗はログに出ない
  - 画面の中央にタイトルが出たかは、報告が無く未確認
- 3 回目に向けて変えたこと: 「Preserve Title Texts」の書き方をやめ、タイトルの文字列から目印を引いた結果をそのまま出す（`(#hud_title_text_string - $info_hud_marker)` を `#text` へ）。調査用に、文字列そのままの行と、式を通すだけ（引き算なし）の行も並べてある。タイトルは送り直しの間隔より長く（200 tick）出しておく
- 利用者の追加の報告: 文字が二重に見えた（明るい文字の裏に暗い文字）。ラベルの `"shadow": true` によるものなので `false` にした
- 3 回目の確認の結果
  - 文字列そのままの行と、式を通すだけの行は `infohud:06:58 X:-28 Y:70 Z:48` と出た。式の結果を `#text` に入れること自体はできる
  - 目印を引く行（`(#hud_title_text_string - $info_hud_marker)`）は、1 文字ぶんの黒い背景だけで文字が無かった
  - 画面の中央に `infohud:...` は出なかった。同じ引き算を使ったタイトル隠しは働いている
  - 文字の二重は消えた
- 推定（確かめていない）: 引き算の結果が数字や `-` で始まると（`06:58 ...`、2 回目の `--:--`）、文字として出ない。式を通すだけの行は `infohud:...` で始まるので出た
- 4 回目に向けて変えたこと: スクリプトが目印のすぐ後ろに色の指定 `§f` を挟む（引いた結果が `§f06:58 ...` になり、数字で始まらない）。比較用に、目印を変数でなく直接書いた行と、`info` だけを引く行を並べてある
- 4 回目の確認の結果: 3 行とも期待どおりに出た（`06:58 X:-28 Y:70 Z:48` が 2 行、`hud:06:58 ...` が 1 行）。`§f` を挟む対策が効いた。目印を変数で書いても直接書いても同じ結果
- 仕上げ: 調査用の行を消して 1 行にした。入ったときのチャットの 1 行（`[Info HUD] スクリプトが動いています`）も消した。この仕上げの版は、まだゲームで確かめていない

- 2026-11-14、利用者の指示で文面を変えた: 「X Y Z と書くのは冗長」。4 つの案から利用者がカンマ区切りを選んだ。`06:58 X:-28 Y:70 Z:48` → `06:58  -28, 70, 48`（ゲーム本来の座標表示と同じ並べ方）。そのあと利用者がローカルのワールドで見て「表示は問題なかった」と報告した

## 出来上がった仕組み

- スクリプトは `infohud:` + `§f` + 文面をタイトルとして送る（文面が変わったときと、5 秒ごと。出しておく時間は 10 秒）
- 左上の行は、タイトルの文字列から `infohud:` を引いたものをそのまま出す
- 中央のタイトルは、文字列に `infohud:` が含まれるときは出さない
- 当初の方針にあった「目印の付いたタイトルを覚えておく」仕組みは使っていない。ほかのタイトルが出ている間は、左上にそのタイトルの文字が出る

## まだ確かめていないこと

- ほかのタイトル（`/title` など）が中央に普通に出るか
- ペーパードール（左上のプレイヤーの絵）が出ているときに重ならないか。ゲームの座標表示はその下に出るが、この表示は `insert_front` で一番上に入れている
- Realm でのパックの更新と、リソースパックの配られ方

## 分かっている危険

- JSON UI はゲームで動かして確かめるしかない。定義が間違っていると、表示が出ないか、タイトルが中央に出る。Realm へは、ローカルで確かめてから入れる

## 表示位置の調整（2026-11-14）

- 利用者の希望: ワイドモニターで遊んでいて、表示が画面の本当の左上に出る。画面の中央に 16:9 の枠を置いたときの、その左上に出したい
- 変えたこと（ゲームでは未確認）
  - 画面の中央に、高さが画面いっぱいで幅が高さの 16/9 倍の枠（`info_hud_area`、`"size": ["177.78%y", "100%"]`）を置き、表示をその左上に入れた。枠は `root_panel` に `insert_front` で足す
  - 画面が 16:9 より狭いときは、`"max_size": ["100%", "100%"]` で枠が画面の幅に収まり、表示は画面の左上になる
  - 表示をチャットの欄（`chat_stack`）から出したので、16:9 以下の画面ではチャットの文字と重なる。代わりに高さ 34 の空きを `chat_stack` の先頭に入れて、チャットを 3 行ぶん下げた。行数を変えたらこの高さも直す
- 書き方の根拠: バニラの `hud_screen.json` に `"size": ["100%y", "80%"]` と `"max_size": ["100%", "50%"]` の使用例がある

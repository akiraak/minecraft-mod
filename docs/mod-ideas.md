## 作れる範囲（確かめたこと）

`@minecraft/server` 2.11.0（安定版）の型定義 `index.d.ts` に有るか無いかを見た。**型定義に有ることと、Realm のゲームで期待どおり動くことは別**で、後者はどれも確かめていない。

| やりたいこと | 型定義 | 使うもの |
| --- | --- | --- |
| データを残す（ワールド・プレイヤーごと） | 有り | `setDynamicProperty` / `getDynamicProperty` |
| コマンドを足す | 有り | `customCommandRegistry.registerCommand`。名前に名前空間が要る。`cheatsRequired: false`、`permissionLevel: Any` を指定できる |
| 選択肢や入力欄の画面を出す | 別モジュール | `@minecraft/server-ui`（npm の安定版は 2.3.0）。Realms で使えないものの一覧（Microsoft Learn）には入っていない |
| ロケーターバー（経験値バーの上の方角の帯）に目印を出す | 有り | `player.locatorBar.addWaypoint`、`LocationWaypoint`（場所）、`PlayerWaypoint`（プレイヤー） |
| 死んだことを知る | 有り | `world.afterEvents.entityDie` |
| 出入りを知る | 有り | `playerJoin` / `playerLeave` / `playerSpawn` / `playerDimensionChange` |
| バイオーム・月齢・向き・明るさ・スポーン地点 | 有り | `getBiome`、`getMoonPhase`、`getRotation`、`getLightLevel`、`getSpawnPoint` |
| 天気 | 一部 | 変わったときのイベント `weatherChange` は有る。今の天気を聞く `getWeather` は無い |
| アイテムを使った・ブロックを壊した／置いたことを知る | 有り | `itemUse`、`playerInteractWithBlock`、`playerBreakBlock`、`playerPlaceBlock` |
| チャットの文字を読む | 無し | `chatSend` は安定版に無い。チャットで操作する形は作れない |

## アイデアの一覧

大きさは目安（小: 半日まで、中: 数日、大: それ以上）。「仕組み」の S はスクリプト、UI は `@minecraft/server-ui` の画面、HUD は Info HUD の文面に足すもの。

## MOD を作らなくてもできそうなこと

確かめていないので、ゲームの設定で見てから判断する。

- 仲間のいる方角: ゲーム本体にロケーターバーの機能がある。Realm のゲーム設定でオンにできれば、仲間の方角は MOD なしで出る
- みんなが寝なくても朝にする: ゲームルール（寝る必要のある人数の割合）で変えられる

## おすすめ

聞いた 3 つの不便に、小さいものから順に当てる。

1. **死んだ場所の記録（5）と 死んだ場所ナビ（6）**: いちばん小さく、困る場面がはっきりしている。Info HUD に 1 つ足すだけで済む
2. **場所メモ（1）と 行き先ナビ（2）**: 「場所が分からなくなる」に正面から答える。6 と同じ「ある場所までの距離と方角を出す」仕組みを使い回せる。コマンドと画面を初めて使うので、Realm で動くかの確認を兼ねる
3. **最後に来た日（9）と 置き手紙（10）**: 時間が合わない友人どうしで効く。2 で確かめた画面の仕組みを使う

お墓（7）は、失敗したときに持ち物が消える危険があるので、ほかで経験を積んでからにする。

## 進め方についての注意

- どれも Info HUD（`addons/info-hud/`）に足す形になる。スクリプトから画面へ文字を渡す道が 1 本しかないため（`CLAUDE.md`）
- Realm のパックを新しい版に入れ替える手順がまだ分かっていない（`TODO.md` の info-hud の Step 6）。先にそれを済ませると、以後の入れ替えの手間が分かる
